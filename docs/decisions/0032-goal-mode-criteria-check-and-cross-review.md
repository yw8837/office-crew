## Context

A goal ends with a check per confirmed criterion. 0015 set that up in 2026-11 and gathered four revisions (0018, 0019, 0022, 0025), while 0026, 0027, 0028, 0030 and 0031 changed it from the outside; the decisions README asks for a new record after three. Separately, one reviewer decides every criterion alone: it can agree too easily or miss what breaks a criterion, and a single model's verdict is the final word. The user decided to add a cross-review that is chosen on the goal card ("cross-review is a choice you switch on on the goal card"), with a second reviewer who attacks the work, the two verdicts merged by code, and only the disagreements brought to the user.

## Options

1. Keep one reviewer. Cheapest, but one model's blind spot is the verdict.
2. Two reviewers, and ask a model to merge them. Costs a call, and the merge is again one model's opinion.
3. Two reviewers that don't see each other, merged by fixed code rules; a criterion where one side fails it without evidence in a checkable form goes to the user on a card. Off by default, since it costs one more call per check.

## Decision

Option 3, on top of the check that 0015 built. This is the whole check as the code runs it now.

### Who checks and what the check replaces

- **Reviewer** (`reviewPlan`, computed when the card is drafted and again on confirm): the first agent of the team's review stages (every agent with a review role) who isn't the lead, else the first member who is neither the lead nor in the last work stage, else nobody. Never from outside the team (0007).
- **Dropped stages**: review stages without an approval gate that aren't meetings can be skipped unless that skips everything; the card shows them with a **Keep** box and their instruction's first 120 characters. Confirm sends `review: { reviewerId, droppable, drop }`; a different reviewer, a list not equal to the current one character for character, or a `drop` outside it is 409 with the current `review` and `estimate`. No `review` (older screen) skips nothing. With task cards (0018) the team's stages don't run and the Keep boxes are hidden.
- **Run shape**: the remaining stages, then `{ label: "Criteria check", agentIds: [reviewer] (+ the second reviewer, below), mission: 'review' }`. A team without a reviewer ends without a verdict (`#noReviewer`: every criterion `unknown`) and asks without "once more".

### One check

- **Run once** (0015): a new CLI conversation; no conversation id, usage baseline or role-note hash read or written; no earlier conversation, memory, handoff note or question box; not stored in project memory; the answer is `once` and doesn't count as the agent's own answer. Instructions sent to the reviewer during the check become goal extra instructions. It counts as that agent's run for the one-CLI-per-agent wait of 0031.
- **Permission**: a single reviewer runs with its own saved permission (decided by the user, 0017); the card says whether it can run commands. It never gets the browser connector (0029) or the repeated-failure note (0030); the daily budget doesn't lower its effort, and automatic routing avoids the AIs that made the reviewed work (build-role outputs, else the last stage); a reviewer on the same AI gets a notice.
- **Before it starts**: pause, the call cap (`#capCheck`, 1 call; ask "20 more" at the cap of 40), the subscription cap (0026, `#limitCheck`).
- **Prompt** (`reviewPrompt`): the confirmed goal, criteria with ids `c1…` and their check methods, out of scope, the work folder, must-keep items, a permission line, the rules (only what it ran or read is `pass`; a breach is `fail` even if minor, but a `fail` needs evidence, else `unknown`; problems outside the criteria go to `extras`; a broken must-keep item to `keepBroken`; don't ask). A 16-hex one-time value and the block example close it.
- **Material** (inside random markers, reference only): `git status --porcelain` (50 paths, `core.fsmonitor` off, no optional locks, 5 s; changed test files get a log line), and each remaining work stage's latest answer (first 1,500 characters; task cards per card as "step · k1"; stages after a return that didn't run again are named as stale, without text; an accepted blocked result (0018) and a card skipped at a usage limit (0019) are a code line saying the result is empty; a card whose claimed files didn't change gets 0025's code line). Not given: research, the meeting, the plan, extra instructions.
- **What the user decided** goes to every reviewer under 0028's headings: answers to meeting questions, the option the user picked between two (0031, its summary inside markers), and answers to questions the lead asked for a card (0031).
- **Accepting a verdict** (`parseReview`): one closed fenced `oc-review` block, last in the answer, with the one-time value, and no other block of the 0022 table anywhere (`oc-lead` and `oc-meet` included, so a reviewer can't ask the lead or call a meeting). Ids are read case-insensitively, unknown ids dropped, missing ids `unknown` (and listed as `omitted`), verdicts other than `pass`/`fail`/`unknown` are `unknown`, a `pass` or `fail` without evidence is `unknown`, the same id twice keeps the worse; `extras` and `keepBroken` up to 5 lines (200/500 characters), copied example lines dropped. The criterion text is always the code's.
- **When it fails**: a broken block is asked for once more with a new value (a verdict that comes then is a normal verdict, not a hole); then no verdict (`fail: 'hole'`). An error is no verdict (`unknown`), a skip too, a stop stops; a usage limit with no takeover opens 0019's wait (later, retry the same round, accept without a verdict, stop) and the cut answer is marked `review.quota`.

### Cross-review (new)

- **Choosing**: the goal card's review part has a **Cross-review** switch, off by default, with "+1 call per check"; a team setting `crossReview: true` (team editor, "Cross-review by default") makes it start on. The card carries `cross: { can, on, secondId, secondName, ai, sameAi, worked, why }`. It is locked with the reason when `why` is `none` (no reviewer), `few` (nobody besides the lead and the first reviewer) or `signin`. It warns when the two share a company (`sameAi`) and when the second is also in a team stage that isn't review-only (`worked`: it may check its own work).
- **Confirming**: confirm sends `cross: { on, secondId }`; on with a second reviewer that differs from the one computed now is 409 with the current `cross` and `estimate`. Off or absent (an older screen, even with the team default on): exactly the one-reviewer check above (stages, calls, prompts, permission and records unchanged).
- **The second reviewer** (`crossPlan`): a team member who is neither the lead nor the first reviewer and whose AI is signed in now (the detection 0027 uses). Preferred: someone who doesn't do the work (a review role) first, then an AI of another company than the first reviewer's (`aiKey`; automatic routing counts as the same, since its AI is unknown), then team order. The goal stores `cross: { on, secondId }`; the check stage lists both reviewers, so continuing a cut goal compares the second too (a second deleted while cut keeps its place, see below).
- **Each round** (`#crossOk`): the round is a one-reviewer check without asking, with one progress line saying why, when the second was deleted, is the first reviewer, isn't on the team, isn't signed in, fewer than `CROSS_WORST` (4) calls are left under the cap (both reviewers asked once more for the format), or its AI is full or over the subscription cap (an AI the user chose to continue on in this goal still counts as allowed). That reviewer still runs read-only, as the card said.
- **Running both**: otherwise both run at the same time, each once in a new conversation and **read-only for that call** whatever their saved permission (`--permission-mode plan` and the equivalents of 0017, also after a takeover), each with its own prompt built from the same material, so neither can see the other's answer. The second gets one different sentence: a red-team reviewer who looks for cases that break a criterion, things left out and claims without evidence. Both write the same block; each gets its own format retry.
- **Merging** (`mergeReviews`, code only), per criterion: both `pass` = pass; a `fail` with **evidence in a checkable form** on either side = fail; a `fail` without it (one side or both) = **split**, with its shape kept as `splitWhy` (`pass`: the other passed, `both`, `unknown`: the other couldn't check); anything else = `unknown`. `extras` and `keepBroken` are the union of both.
- **One side missing**: a side that left a criterion out, or whose block or call failed, gives the other side's verdict as it is, marked "one reviewer only" (`one`); the failed side gets a progress line with the failure kind of a missing verdict (`hole`, `unknown`, `outside`), and a usage limit there opens no wait.
- **Both missing**: each side gets a progress line with its reason, and the round is today's failed check: a usage limit on either side (with no takeover) opens 0019's wait, and a retry runs both again; otherwise the first reviewer's reason.
- **Evidence in a checkable form** (`hasEvidence`): a file location (`folder/file.ext`, `file.ext:12`, `file.ext#L4`, Unicode names too; the extension all lower or all upper case, and a one-letter name with a one-letter extension such as `e.g:1` doesn't count), an address starting with `http://` or `https://`, a command or code in backticks (three characters or more with a space, a path sign, a bracket, a dot or similar), a quote of twelve characters or more (`"…"`, `“…”`, `「…」`, `『…』`), or an exit code (`exit code n`, `exit status n`, `종료 코드 n`). A backtick span or quote holding only criterion ids and verdict words (`pass`, `fail`, `ok`, `합격`, `불합격` …), wording alone ("doesn't look right"), a bare file name or a dot between sentences (`output.Then`) doesn't count. **The code checks only the form**: whether that file, line or output exists is not checked, so a made-up path counts.
- **Judgment card**: when a criterion is split, the run waits (`hold: { reason: 'mission', kind: 'split', round, names, items }`; attention kind "verdict"; the flow stage's gate after the check). Every criterion shows both verdicts and evidence side by side, marked as written by agents, and each split criterion a line for its shape. Each split criterion takes **Fail it: have it fixed**, **Pass it: close it** or **Hold** and an optional one-line reason (200 characters), with nothing picked in advance; the card says that a reason reaches the agent only for a criterion you fail.
- **Answering the card**: `control` `judge` with `{ round, picks }` is the only answer besides stop: another wait's action, another round or a repeated request is `ok: false`; a pick missing for a split criterion or naming one that isn't split is 400. Fix = `fail` with the failing side's evidence, close = `pass`, hold = `unknown` that this round's return leaves out (and the report lists); the choice is stored on the criterion as `user: { pick, note }` and the merged result then follows the flow below. Two user-marked log lines: what was picked, and (only when there are reasons) the reasons, marked `typed`. A reason on a fixed criterion reaches the return prompt after the reviewers' marked block as "[Decided by the user on the judgment card — the user's words]", with `<` `>` full-width.
- **The card's values** are kept in `mission.split` until they are applied. A goal cut while the card waits shows the same card again on continue, without a call; a cut goal without those values checks that round again. Stopping at the card, or discarding the cut goal, clears them, so the flow map and the export don't show a waiting card.

### After the verdict

- In order: stopped → `stopped`; unused extra instructions → ask (use them and go once more / end / stop); all criteria `pass`, no open question and no broken must-keep item → `done`; a `fail`, returns left (`RETURN_CAP` 1), no broken must-keep item and no "no progress" → automatic return; else ask (accept → `accepted` / once more, which sets `returnCap = returns + 1` / stop; no "once more" without a reviewer).
- **Nothing to return**: in a goal with cross-review, when no criterion is left to send back (the rest were held), the question offers accept or stop only (`more: false`, `noReturn`; the box says why). Goals without cross-review keep "once more" there, as before.
- **Return**: the last work stage (with task cards, the last card step and the raised steps after it, 0027) runs again with `returnPrompt` (failed and `unknown` criteria except held ones, evidence 300 characters, random markers, reference only), the stage's previous result in markers unless its conversation continues, and the assumption line when it is the second return or a criterion failed twice in a row. A meeting stage is redone by the lead alone; an approval stage asks again; later stages don't run again and the next check names them as stale.
- **No progress** (0028, `sameFails`): when the same criteria fail with the same evidence after another try, no automatic return, a line in the verdict box and the log.

### Records

- Answers: `review: { round, results, missing, retried?, quota?, role? ('check'|'red'), extras?, keepBroken? }` and `reviewBlock`; the chat hides the block and shows the table ("written by an agent · not confirmed by you"; cross-review tables say whose verdict before merging). Kinds (`answerKind`): `review`, and `cross` for the red-team answer, next to 0031's `fork` and `lead`; the report lists `cross`, `fork` and `lead` only when there are some.
- Goal: `reviewerId`, `dropped`, `round`, `returns`, `returnCap`, `calls`, criteria `status`/`evidence`/`one?`/`user?`, `extras`, `keepBroken`, `repeatFail`, `noProgress`, `cross`, `crossLog` (per round: reviewers, verdict counts, split and one-reviewer criteria, picks, `single`/`none`; 20 rounds), `split` while a card is open. Log lines: review (`fail` `review`/`outside`/`unknown`/`hole`), keep, extra, git, no-progress, ask and answer lines, `cross` lines.
- Report (0025): final verdicts with evidence (200 characters); a **Cross-review** part (two reviewers, rounds, rounds with one reviewer, split criteria, what you chose, held and one-reviewer criteria); into memory only with **Add to memory**.
- Export (0030): `goal.reviewer2`, `crossLog`, an open card as `splitOpen`, calls of kind `cross`; without answer text, the judgment card's reason lines are exported without their text, like extra instructions. Flow map: the red-team check and the judgment cards as side boxes of the check.
- **Estimate** (0019): the check is 1 call and each automatic return adds the return stage + 1; with cross-review the check is 2 (`estimateParts.cross`, `sumEstimate` `cross`, the plan estimate too), so the card's range grows by 1 + the returns. 0031's two-option summaries add to the maximum separately.

## Consequences

- One reviewer is unchanged in cost and behaviour. Cross-review costs one more call per check (up to four calls in a round when both get a format retry), runs both reviewers read-only (they can't run tests), and asks the user only about criteria where a fail has no evidence in a checkable form.
- Fixed prompt text: the red-team prompt is the check prompt with one sentence changed, 113 more characters in Korean and 215 in English (`reviewRedPrompt` in `test/prompt-baseline.json`); the one-reviewer prompt is the same as before.
- Checked with fake CLIs in the tests, and the code's key checks (merge rule, evidence form, cap check, read-only, applying a card once, clearing the card) were each broken on purpose once to see a test fail.
- Screens checked in the app's built-in browser (fake CLIs marked as signed in, a temporary data folder, not port 4317), in Korean, at a 1,025 px and a 420 px window:
  - First version: the card's switch (off by default; the estimate 4–6 → 5–8 with stages and 4–12 → 5–14 with task cards), toggled with Tab and Space; the team editor's "Cross-review by default" saved, and a new goal card starting with the switch on; the flow stage's "my turn" pill moving focus to the judgment card; the card at 420 px (two columns of 161 px, no horizontal scroll) answered with the keyboard (radio, reason, Confirm); fixing with a reason (the return prompt had it outside the reviewers' markers), folding in round 2, holding and accepting; the report's Cross-review part and answer counts; the flow map's side boxes at 420 px with the arrow keys; the progress tab's lines and the "decided by you" chip.
  - After the review: the goal card's warning that the second reviewer is also in a work stage; the judgment card's new lines (evidence form only, where a reason goes, each criterion's shape for "one passed" and "both failed", at 1,025 and 420 px); holding the only split criterion, after which the question offered only accept and stop with the line saying why, and listed the held criterion with its chip and the reason; the report listing the picks and the reasons on separate lines.
  - Not checked on screen: English, Simplified Chinese and Japanese (the translation test only), a dark theme, a screen reader, the "other couldn't check" shape, the 409 redraw and a cut card shown again (tests only).
- Not covered: how real CLIs follow the block and how well a red team attacks are not measured (fake CLIs only); "same company" is the AI key of the agent's setting, and an automatically routed second reviewer isn't steered away from the first reviewer's AI; a usage limit on one side gives a one-reviewer verdict instead of a wait; a held criterion makes the goal end `accepted`, not `done`; the user's reason is an instruction only for fixed criteria.
- Not covered (who checks): a reviewer that has a review role and is also in a work stage can check its own work, and when the team has only one candidate the second reviewer can be someone who did the work (the card says so).
- Not covered (read-only): the reviewers still get the agent's own connectors (the app doesn't remove them for read-only turns, as with research turns), and whether the CLI holds a connector's tools back in read-only mode isn't checked; on an AI that can't enforce permissions (`permissions: false`: API, local models, Hermes) read-only is a written instruction, also after a takeover, as for research turns.
- Not covered (from 0015): "don't change files" for a single reviewer is an instruction; returns redo only the last work stage; the cap can be passed by retries and takeovers inside a stage; criteria can't be changed after confirming.
- To undo cross-review: stop sending `cross` from the card (or confirm with it off); goals then run the one-reviewer check. To undo the check: confirm without `review` and drop the check stage from `#missionPlan`.
