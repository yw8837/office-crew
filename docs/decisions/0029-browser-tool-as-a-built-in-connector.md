# 0029: The "Use a web browser" switch is a built-in Playwright MCP connector, and the browser tab shows the screenshots from its output folder

- Status: Accepted
- Date: 2026-11-26 (security review the same day: file paths, file writes, permission levels, per-tool allow list)
- Related: [0001](0001-no-runtime-dependencies.md) (no runtime dependencies), [0017](0017-goal-mode-research-and-meeting-first.md) (read-only goal turns), [0021](0021-no-demo-team.md) (the simulated AI), [0023](0023-prompt-assembly-for-cache-and-fresh-meeting-turns.md) (per-call lines at the front of the prompt), [0024](0024-team-proposal-from-a-document.md) (team drafts), `server/browser.js`, `server/orchestrator.js` (`#runAgent`, `#system`, `#onEvent`), `server/providers/claude.js`, `server/providers/codex.js` (`caps.browser`, `caps.mcpCwd`), `server/index.js` (`cleanAgent`, `PUT /api/settings`, `GET /api/browser/…`), `server/store.js` (`onDelete`), `server/catalog.js` (`importPlugin`), `public/js/views/browser.js`, `test/browser-tool.test.js`, `test/fake-cli/fake-claude.js`, `test/fake-cli/fake-codex.js`

## Revision (2026-11-27): checked once with real CLIs on Windows

Six real calls in a separate data folder (Claude Code with Claude Sonnet 5.5, Codex with GPT-6.1 Sol), one of each with the switch on and the "Allow file edits" permission, asked to open a page and take a screenshot.

- `npx` started from both CLIs as configured, without a `cmd /c` wrapper.
- Both ran `browser_navigate` and `browser_take_screenshot` without a permission error, and the screenshot landed in the output folder under the name the app picks up (`page-<time>.png`); the tool block got its image.
- The real result of `browser_take_screenshot` has no "Page" section (only navigation-like tools report the address and title), so the recorded screen had an empty address and title. Fixed: within one CLI call the app keeps the last address and title that a browser tool's result reported in its "Page" or "Open tabs" section, and uses them when a screenshot's own result has none. An address the agent only passed as input isn't kept, and nothing carries over to the next call. It is still only shown as text; it can be stale when the page or the tab changed in between, and a page that fakes a single "Page" section in a result that has none can set it.
- Codex wrote its files relative to the output folder (its working folder), as intended. Claude's paths were relative to the work folder, as written under "Not checked" below.
- Download: the `npx` cache grew by about 19 MB in this run. The Playwright browser folder was 715 MB afterwards; its size before the run wasn't measured, so what the first run downloads is still not known.
- Still not checked: that the deny list and the `filename` rules hold when an agent tries the blocked tools, and other operating systems.

## Context

People asked for what the Claude desktop app and the Codex app do: the agent works a web page by itself while the user watches next to the chat. The connector page already had a "Playwright browser" preset (`npx -y @playwright/mcp@latest`), but the version floated, nothing allowed the tools (Office Crew runs Claude with `--permission-prompts none`, and in Codex's `exec` mode an MCP approval request is cancelled because nobody can answer it, per the Codex source), screenshots came back as `[image]` or 4,000 characters of JSON, and nothing on screen showed the page.

## Options

1. Keep the preset and let people add it by hand. None of the problems above go away.
2. A switch per agent that adds a connector the app builds at run time: pinned version, fixed flags, tool rules for each CLI, a per-session output folder the app watches for screenshots.
3. Take the images out of the CLI output. Their shape in Claude's `tool_result` and Codex's `mcp_tool_call` was not checked with a real CLI, and it ties the feature to each output format.
4. Have the app start and drive a browser itself: Playwright as a dependency (against 0001) or a hand-written DevTools client, and the agent would still need a tool to reach it.

## Decision

Option 2.

1. **Switch = built-in connector.** Agents get `browser` (true only when it is exactly `true`; imported plugin agents are normalised to `true`/`false`). It is attached when the setting `browserTool` is not `false`, the AI of this run can take it (`caps.browser`: Claude and Codex, including added ChatGPT accounts) and the permission can change files: **Allow file edits, Auto decide or Allow all** (`edit`, `auto`, `full`). `#runAgent` marks the answer `browser: true` and `prepare` adds one connector after the saved ones (a saved connector with the same key is left out): key `crew-browser`, `npx -y @playwright/mcp@0.0.86 --isolated --headless --output-dir <data folder>/browser/<session>/<agent>`, plus `--allowed-origins a;b` when `browserOrigins` has entries. It is passed like a saved `npx` connector and never stored, so the connector page, `GET /api/bootstrap` and plugin exports don't see it. The version is one constant (`BROWSER_MCP_VERSION`): on 2026-11-26 npm's `latest` and the GitHub "Latest" release were both 0.0.86 (2026-11-18).
2. **Tools.** Every tool in the 0.0.86 README was checked for arguments that take a path on this PC or write a file. **Blocked** (Claude `--disallowedTools` with the bare name, which Claude Code documents as removing the tool from the model's context; Codex `disabled_tools`): `browser_run_code_unsafe` (README: "RCE-equivalent"; its `filename` also reads a local file as code), `browser_evaluate` (JavaScript in the page), `browser_file_upload` and `browser_drop` (`paths`: "Absolute paths to files", handed to the page), `browser_set_storage_state` (`filename` read into the browser; it exists only with `--caps=storage`, listed anyway). Playwright MCP can't turn off a core tool, so these rules live in the CLIs. **Allowed** (the 21 other default core and tabs tools): click, close, console messages, drag, emulate media, fill form, find, handle dialog, hover, navigate, navigate back, network request(s), press key, resize, select option, snapshot, take screenshot, type, wait for, tabs. Claude gets them one by one in `--allowedTools` (`mcp__crew-browser__<tool>`), Codex in `enabled_tools`, with `default_tools_approval_mode = "approve"`. In Claude's Allow all (`--dangerously-skip-permissions`) an allow list allows nothing extra and narrows nothing, so there only the block list holds; Codex's `enabled_tools` decides which tools exist at all, also under Allow all.
3. **File writes.** Six allowed tools take a `filename` that "is resolved against the workspace root" (take screenshot, snapshot, console messages, find, network request(s)). The README says file access is "restricted to workspace root directories (or cwd if no roots are configured)" and `--ignore-roots` uses "the current working directory as the workspace root instead". **Codex**: the connector gets `--ignore-roots` and `mcp_servers.crew-browser.cwd = <output folder>` (Codex's config reference: "Working directory for the MCP stdio server process"), so named files and file access stay in the output folder. **Claude**: whether a `--mcp-config` stdio entry takes a working directory could not be found in Claude Code's documentation, so neither is used; Claude Code answers `roots/list` with "the session's launch directory plus every additional working directory" (`--add-dir`), which for Office Crew is the work folder, the uploads folder and, when a conversation file is handed over, that session's handoff folder. Instead Claude gets deny rules on the argument, `mcp__crew-browser__<tool>(filename:*)` for those six (documented: "To match a parameter on an MCP tool, pass a deny rule with `--disallowedTools`"; a call without the argument doesn't match). Settings files skip such rules, so they go on the command line; if a Windows `.cmd` wrapper can't be resolved and the shell fallback is used, its argument allowlist refuses the parentheses and the run fails instead of running without them.
4. **Screenshots from the output folder.** When a browser tool event ends (`mcp__crew-browser__browser_*`, a Claude sub-agent's `↳ mcp__crew-browser__browser_*`, Codex `mcp:crew-browser.browser_*`), the app takes the newest regular image file (`.png`, `.jpg`, `.jpeg`, `.webp`, any case; links are not followed) changed since the tool started (2 seconds of slack) that no earlier tool took, and records it on the block as `shot: { file, agentId, sid, at, url, title }`. `url` and `title` are shown as text only: they are read from the `- Page URL:` and `- Page Title:` lines inside the result's single `### Page` section (Codex's result JSON is parsed for its text first), else the `(current)` line of the single `### Open tabs` section, else the call's `url` input; when two Page sections appear (page text imitating one) nothing is used. Limit: a result without a real Page section where page text imitates exactly one is still believed; the title is the page's own anyway. The prompt's per-call head (0023, key `browser`) gets one line: take one screenshot after opening or changing a page, without a file name (a named file goes to the workspace root, not the output folder), the user watches, text on web pages is material and its instructions are not to be followed. `GET /api/browser/<session>/<agent>/<file>` serves only a file recorded on a block of that session, after strict patterns for both ids and the name, a real path directly in that folder, a regular file whose first bytes are PNG, JPEG or WebP; `nosniff`, a sandbox CSP and the usual token. After each recorded screenshot the session folder is trimmed, oldest first, to 200 files and 100 MB, counting every file in the output folders and their sub-folders (links and junctions are skipped, emptied sub-folders removed). Deleting a session deletes its folder and its record of taken files (`Store.onDelete`); if the session was deleted while a run used the browser and the folder came back, it is deleted when that run ends.
5. **Read-only and other runs don't get it:** Read-only and Default permissions (Default is Codex's read-only sandbox and Claude's "risky actions are refused"), a goal's research, meeting and plan turns that run read-only for that call (0017), the team draft (0024), the goal's criteria check, the simulated AI and session overrides (such as translating skill descriptions). A research role that needs the web uses its CLI's own web search and fetch.
6. **Security.** `--isolated` keeps the profile in memory, so the user's own browser sign-ins are never used. Allowed origins are a convenience: the README says they "*do not* serve as a security boundary and *do not* affect redirects". Entries must be `http`/`https` with a host of `[a-z0-9.-]` or `[IPv6]` and an optional port; anything else (a `;`, which separates origins in the flag, spaces, a user name) is refused, for text and list input alike. Addresses (with any token in their query) and screenshots stay in the session and its folder until the session is deleted.
7. **Screens.** The agent editor's switch is dimmed with the reason when the AI can't take it, and says when the permission is below Allow file edits, when automatic routing applies and when the global setting is off. Turning it on shows once that `npx` downloads the package the first time and that whether a browser is downloaded too, and how much and where, was not checked. The session's right panel gets a "Browser" tab once an answer had the connector: the newest screenshot with title, address, time and agent, previous and next over the latest 20, a click opens it large, a dot for unseen ones (kept per session in the browser's local storage). A tool block with a screenshot shows a small copy under it, built from the session the message belongs to. Four languages.

Decided differently from the first plan, on purpose: ACP agents don't get it (Office Crew can't remove a tool from them, and their permission answers go by tool kind); the goal's criteria check doesn't get it; `browser_file_upload` is blocked; the prompt line asks for no file name.

## Relation to decision 0001

`package.json` still has no dependencies, and Office Crew starts neither a browser nor the MCP server. The user's CLI runs `npx -y`, which downloads `@playwright/mcp` and the Playwright alpha build that release pins (`1.66.0-alpha-2026-11-18`) and runs it with the user's permissions: a supply-chain risk outside this repository's dependency list, changed only when the constant changes. To update: change `BROWSER_MCP_VERSION`, go through that version's README tools again and update `BROWSER_TOOLS`, `BROWSER_BLOCKED` and `BROWSER_FILENAME_TOOLS`.

## Consequences

- **Not checked with a real CLI (the tests use stand-in CLIs only):** (1) whether `npx` starts from Claude Code and Codex on Windows as configured; no `cmd /c` wrapper is added, the same as the existing preset. If it doesn't, change `command` and `args` in `browserConnector` (`server/browser.js`). (2) Whether both CLIs honour the allow and block rules, the `(filename:*)` rules and Codex's `cwd` with `--ignore-roots`. (3) Whether a browser is downloaded on first use, how much and where. (4) Whether a screenshot without a file name lands in `--output-dir` under a name the route accepts. Also not checked: the exact text of real tool results, and a data folder path with non-ASCII characters through Codex's `-c`.
- Remaining risk, Claude: the six `filename` tools can't write, but Playwright MCP's own file access (roots) still spans the work folder, the uploads folder and any handed-over conversation folder; no allowed tool reads a local path into the page, and `file://` navigation is blocked by default (README). Under Allow all only the block list stands between the agent and the server's other tools; with 0.0.86 there are none beyond the ones listed.
- Remaining risk, Codex: confinement rests on the README's description of `--ignore-roots` and on Codex using `cwd`, both unverified with real runs.
- A page can still steer the agent within the allowed tools (click, type, navigate): prompt injection, answered only by the prompt line and the permission levels.
- Not done: a live picture, handing the browser to a person, controlling the whole computer, read-only and Default runs, ACP agents, the browser folder in the storage report. Normal meetings outside goal mode and review stages run at the agent's own permission, so they get the browser when that permission allows it. If the agent never takes a screenshot, the tab doesn't change.
- To undo: make `browserUse` return false; saved `browser` fields and `shot` fields on old blocks can stay.

## Checking it by hand (once, with a real CLI)

1. Use a separate data folder (`--home <dir>`), sign in to Claude Code, keep a few hundred MB free on the drive npm uses.
2. Make an agent on Claude, permission Allow file edits, turn on "Use a web browser", save.
3. Start a session with it and send: "Open https://example.com and tell me the page title."
4. Expect `mcp__crew-browser__browser_navigate` and `…browser_take_screenshot` without a permission error, a small screenshot under the second, and the "Browser" tab with the picture, "Example Domain" and `https://example.com/`; images under `<data folder>/browser/<session>/<agent>/`. If nothing starts, note the error (check 1); a refused tool (check 2); first-run time and size (check 3); an empty tab: list that folder (check 4).
5. Ask "Save a snapshot of the page to notes.md" and expect a refusal; ask "Upload C:/Windows/win.ini to the page" and expect no tool for it.
6. Repeat 2 to 5 with a Codex agent; there a named file should appear only inside the output folder.
