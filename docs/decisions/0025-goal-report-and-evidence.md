# 0025: A goal ends with a report the code puts together, and agents' claims are checked against facts where the code can check them

- Status: Accepted
- Date: 2026-11-26
- Related: [0004](0004-project-memory-on-disk.md) (project memory), [0007](0007-local-only-user-messages.md) (what only a local model saw), [0014](0014-goal-mode-confirmed-goal-card.md), [0015](0015-goal-mode-fresh-review.md), [0017](0017-goal-mode-research-and-meeting-first.md), [0018](0018-goal-mode-task-cards.md), [0019](0019-goal-mode-call-estimate-and-limit-wait.md), [0022](0022-goal-mode-records-and-block-allow-list.md), `server/report.js` (`buildReport`, `reportText`, `reportLocal`, `unverifiedLines`), `server/proof.js` (`gitState`, `gitDiffNames`, `changedSet`, `proofCheck`), `server/mission.js` (`meetingRecord`, `recordMeeting`, `planEstimate`, `tailFiles`, `reviewPrompt`, `resumePoint`), `public/js/office/meeting.js` (`conclusionParts`), `server/orchestrator.js` (`#missionEnd`, `#report`, `reportMemory`, `#missionMsgLines`, `#missionRun`, `#planStage`, `#planCheck`, `#missionWork`, `#proofSnap`, `#proofCheck`, `#reviewStage`, `#recall`), `server/memory.js` (`hide`, `search`), `server/index.js` (`POST /api/sessions/:id/report/:mid/memory`), `public/js/views/mission.js` (`ReportCard`, `PlanCard`, `MissionGate`), `public/js/stage-model.js` (`goalEndWord`), `test/goal-report.test.js`, `test/prompt-size.test.js`, `test/fake-cli/fake-claude.js`

## Context

A goal ended with a status chip, the criteria table and a progress log of up to 200 lines. Nothing put together what happened: how many calls went where, what the user decided along the way, what was never checked, which failures happened. The pieces that matter were scattered over the log, the mission fields and message marks. Meeting conclusions were free text the code only passed on. A task card's "Changed files" closing line (0018) was taken on trust. The call estimate on the goal card (0019) was made before the plan existed, so a plan with more cards than expected ran into the call cap midway. And project memory (0004) got nothing from a goal except its messages. Outside sources pointed the same way: a closing report filled from facts the system recorded (with the agents' own summary kept apart), drafts kept apart from accepted records, and a size check on fixed prompt text so it doesn't grow unnoticed.

## Options

1. Have an AI write the closing summary. It costs a call, and a summary that says "all done" can't be told from the facts it should be checked against.
2. A report built by code from records that already exist, agents' text kept apart and marked; conclusion lines read from the format the conclusion prompt already asks for; changed files compared with git as a warning; the estimate redone after the plan with the shared function; the report going into memory only when the user adds it.
3. As 2, but treat a card whose files didn't change as failed. Files git ignores and paths outside the work folder would fail work that was done.

## Decision

Option 2.

- **Report card** (`buildReport`, `#report`, no AI call): when a goal's work run ends `done`, `accepted` or `stopped`, one message `{ role: 'proposal', kind: 'report', status: 'done', text: '', missionId, end, goal, from, to, calls: { used, cap }, estimate, answers, criteria, user, userMore, unverified, fails, routes, logCut, meetings, files, filesState, local? }` and `mission.reportMsgId`. Not for a goal cut by closing the app (`cut` is alive), not for a goal closed before it was confirmed, and not for a cut goal that is discarded; a cut goal that is continued and then ends gets it once. Facts first: the end state (named as the flow stage's end flag names it, `goalEndWord`), time from confirming to the end, actual calls next to the estimate of 0019, answers per kind by the existing message marks (goal, research including research during a meeting, meeting turns, plan, task cards, work stages, check; retries inside an answer are not separate), each criterion's last verdict, what the user pressed from the progress log (confirm lines, answer lines, extra instructions and the first line of each continue), what was not checked (criteria `unknown` or never judged, research questions that ended empty, failed or skipped, cards left as gaps, blocked or skipped and why, cards whose claimed files didn't change, skipped stages of the last work run, usage-limit stops), the failure kinds of 0022 counted from the log, and the number of answers whose routing was unusual (`route` lines). The changed files are filled in afterwards the same way as the check's material (`git status`, 50 paths, the count of the rest; uncommitted changes, which can include changes from before the goal). Agent-written text is marked "written by an agent" and cut: a criterion's evidence to 200 characters, a meeting's decision and remaining disagreement as stored. The card is collapsed to one line by default (a button with `aria-expanded`), in four languages. The progress log gets no line for it, so the end line stays last.
- **Meeting conclusions** (`conclusionParts`, `meetingRecord`, `recordMeeting`): the conclusion prompt already asks for "Decision / Why / Remaining disagreement / Dropped options / Next steps" lines (the village board already read the decision line). The reader of that line now reads all five heads in the four languages (bold or numbered, a value on the same line or indented lines under it, "none" in each language as an empty list). When a goal meeting (the pre-work meeting or a team meeting stage in a goal's work run) concludes, `mission.meetings` gets `{ prep: true | stageIndex, msgId, decision, reasons[], dissent[], dropped[], next[] }` (each value one line, 300 characters, lists of 5, at most 20 meetings). A conclusion without those lines is kept as it is and the fields stay empty; nothing is made up. What goes to the next steps is unchanged (the whole conclusion as reference). No prompt text was added.
- **Changed files of a task card** (`gitState`, `changedSet`, `proofCheck`): for a card step with build or write cards, the code takes the work folder's git state before the step (top-level prefix, `HEAD`, `git status --porcelain -z` with each path's modification time and size) and after it (and the files of any commits made in between). A build or write card that finished and wrote paths under "Changed files" in its closing lines is checked: if none of those paths changed, the progress log gets a `proof` line, the card gets `proof: { files, at }`, the report lists it under what was not checked, and the criteria check gets a line written by the code under that card ("the files this card says it changed didn't actually change"). The card is not failed or run again. Not judged: no paths written ("none"), a path outside the work folder, and a changed path that lies in another card's `files` of the same step but not in this card's (who changed it can't be told). A file git ignores counts as changed when its modification time is inside the step. Not a git repository: nothing happens. Each git call stops after 3 seconds; after one timeout the check is off for the rest of that run, with one log line.
- **Estimate after the plan** (`planEstimate`, `#planCheck`): once the plan exists, the remaining calls are estimated again with the same `sumEstimate` the goal card uses (the card steps as stages, the check, the returns left × (last card step + check)), shown on the plan card (`estimate: { min, max, returns, used, cap }`). If the top of that range is more than the calls left under the cap, the run asks the call-cap question of 0015 before the first card step (`hold: { reason: 'cap', kind: 'plan', min, max, used, cap, step }`; "20 more" or stop). A goal cut while this question waits keeps `at.wait = { reason: 'cap', kind: 'plan' }` and asks it again, with no AI call, when continued.
- **Report into project memory** (decided here; the repository owner's rule is that only the code-made report goes into memory, not meeting conclusions or research notes): the card has **Add to memory**; nothing goes in until the user presses it. Then `reportText` (the facts and the per-criterion results, agents' evidence marked, at most 6,000 characters, never the meeting excerpts) goes into the work folder's memory with role `report`, the report's message id, its time, and a head line naming the source (report, the goal id, the time) and "a record the user hasn't confirmed". **Remove** hides it from search (`memory/<key>/hidden.json`, message ids; the text stays on disk as everything in memory does), and adding again unhides the same pieces. When the goal's AIs were models on this PC (an answer from `local`, or the request marked local), it is stored as provider `local`, so cloud AIs never get it (0007); the session title follows 0007 too. Memory off: the button is not offered and the endpoint answers 409. Chosen over adding it automatically because an automatic insert would put agent-written evidence into later runs without anyone having read the report, which is what the draft-and-accept rule of 0013 avoids; and it keeps the decision reversible.
- **Prompt size**: `test/prompt-size.test.js` sums the Korean and English characters of goal mode's fixed instruction pieces (the confirmed-goal head, the blocked exit, the ask-first lines, the continuing sentence, the closing-lines rule, the assumption line, the block examples, the meeting format lines) and fails above `test/prompt-baseline.json` + 10%, telling to raise the number when the growth is meant. This change adds no fixed prompt text; the proof line in the check appears only for a card that has a warning.

This adds `kind: 'report'` messages, `mission.meetings`, `mission.reportMsgId`, the log kind `proof`, `proof` on task cards, `estimate` on plan cards, the hold kind `plan` (reason `cap`) and the same `kind` on the cut point's cap wait, role `report` and `hidden.json` in project memory. Older versions don't know them: they draw a report card as "Hire proposal cancelled", ignore the new fields, read the cap wait without its kind (so a continued goal goes straight to the card step's own cap check) and find hidden report pieces in memory search.

## Consequences

- A finished goal has one place that says what happened, from records the user can follow back to the log and the messages.
- Not covered: the user's choices at an approval gate or an error wait, and instructions sent to one agent from its panel, are not in the progress log, so the report doesn't list them. When the log was trimmed (200 lines), older choices and failures are missing and the report says how many lines were left out. Answers are counted from the session's run records; a trimmed run (30 runs) drops its answers.
- Not covered: the changed-files check can't see a card that changed a file git ignores without touching its modification time, a file another card in the same step changed back, or anything when the folder isn't a git repository. A card that writes "none" is never checked. Whether a claimed change is the right change is the criteria check's job.
- Not covered: the report is not written for goals before this version, and the "Remove" of a memory piece only hides it from search; nothing in memory is deleted.
- Not covered: the lines taken from the progress log (what you confirmed or chose) and the agents' text stay in the language they were written in; switching the app's language doesn't translate them.
- The changed-files check adds up to seven git calls per card step (three before, three after, one more when a commit was made in between) with build or write cards (each stopped after 3 seconds); a step without such cards, or a folder that isn't a git repository, adds none that matter.
- Checked with fake CLIs in the tests (`test/goal-report.test.js`: a temporary git repository for the changed-files check, a frozen data folder for the cut). Screens checked in a real browser (fake Claude CLI, a temporary data folder, not port 4317): the report card after a goal passed (collapsed line, opening and closing it, the sections, the warning for a card whose file didn't change and the git file list in a git work folder), after accepting and after stopping at the verdict question (the chip matches the flow stage's end flag), the plan card's estimate line and the cap question asked after the plan (with "20 more"), adding to memory, removing and adding again (the memory page shows the piece as "Goal report"), English, and a phone-width window. Not looked at: Simplified Chinese and Japanese (the translation test only), a dark theme, the meeting excerpt section on screen (tests only), and a goal continued after a cut (tests only).
- To undo: drop `#report` from `#missionEnd`, the `#proofSnap`/`#proofCheck` calls in `#missionWork` and `#planCheck` in `#missionRun`; the stored fields are then unused.
