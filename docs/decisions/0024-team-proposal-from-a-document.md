# 0024: A document attached in the chat becomes a team proposal the user approves

- Status: Accepted
- Date: 2026-11-26
- Related: [0006](0006-hire-proposal-in-chat.md) (the hire proposal this follows), [0013](0013-agents-keep-role-notes.md) (role notes, the injection patterns), [0014](0014-goal-mode-confirmed-goal-card.md) (only what the user confirms becomes instructions), [0017](0017-goal-mode-research-and-meeting-first.md) and [0018](0018-goal-mode-task-cards.md) (run once, a block the code cleans up), `server/teamdoc.js` (`detectTeamDoc`, `docFiles`, `safeWriter`, `teamWriter`, `teamPlan`, `readDocs`, `teamPrompt`, `parseTeam`, `cleanTeamDraft`, `sameDraft`, `writeTeamDraft`, `resolveTeamProposal`), `server/orchestrator.js` (`send`, `#teamDoc`, `#teamDraft`, `#releaseTeamDoc`, `recover`, `#start`, `#runAgent`, `#roleNotes`, `#remember`, `notTalk`, `sendProposed`), `server/index.js` (the proposals route), `public/js/views/teamdoc.js` (`TeamCard`), `public/js/views/session.js`, `public/js/chat-tools.js` (`hideTeam`), `test/teamdoc.test.js`, `test/fake-cli/fake-claude.js`

## Context

People keep notes on which AI, model and effort to use for which kind of work (for example "everyday work: Sonnet medium or Sol medium; hard bugs: Opus high or Astra medium; chores: Haiku low or Luna low"). Turning such a note into Office Crew agents meant making each agent by hand on the Agents page and then a team on the Teams page. Automatic routing picks by role and profile only and can't follow a table like that.

## Options

1. Parse tables with rules and no AI. No usage, but people write these notes in free form; a slightly different table can't be read.
2. One AI call turns the document into a marked block, the code checks and cleans it, and a proposal card waits for the user (the frame of 0006 and 0018). One call, one more when the block can't be read.
3. Let an agent call the app's own API to make the agents and the team. An agent with file or command permission could appear without the user choosing it, the path 0006 turned down.

## Decision

Option 2.

- **Recognizing** (`detectTeamDoc`), word rules in Korean, English, Chinese and Japanese, no AI: one line, at most 120 characters, not starting with `/`, no `@name`; the message ends with a request to make a team, with the team word as the object of the making verb and nothing else between them (narrow like 0006's hire rule; anything may come before it, such as "from this doc"). Korean: 팀 (with 을, 를 or 도, 하나, 새로 or 다시, 좀) then 세팅, 셋팅 or 셋업 (alone or with 해…), 구성, 설정 or 편성 with 해…, or 짜…, 꾸려…, 만들어…, and the sentence ends there; 팀 inside another word (팀장, 팀원, 스팀) doesn't count. English: set up, setup, build, create, make, assemble, form, put together, organize or spin up, then (me|us), articles, then team, then at most a short source phrase (from, with, using, based on… and up to five words, no "and" or "then") and "please"; not after don't, not, never or how to; also "team setup". Chinese: a two-character verb (组建, 搭建, 建立, 组成, 成立, 创建, 配置, 设置, 组织) or 组, 建, 搭 with 个 or 支, then at most four characters, then 团队, 队伍 or 小组 at the end, or 团队 followed by the verb (把团队搭起来). Japanese: チーム (with を or も) then 作, 組, 編成, 作成, 構成, 設定, セットアップ or 立ち上げ in the て form or with ください…, or 作ろう, 組もう…, at the end (チームの… doesn't count). When in doubt the message stays ordinary. And at least one text document attached: a name ending in `.md`, `.markdown` or `.txt` (case ignored), at most 200 KB; only the first three are read. Without a text document (no attachment, or pictures only) the message is an ordinary message. Only messages a person sends from the chat are checked, before goal mode and before hire recognition, and never while a run is going (the message then queues or steers as before). Uploads already took any file; nothing changed there.
- **Writing the draft**: the user's message is stored with `teamDoc: true` and starts a run with one stage, "Team draft", whose only agent is the writer: the session team's lead (the goal-mode rule) → the session's agent → the default agent in Settings, skipping agents set to the simulated AI, agents whose AI isn't signed in, and agents whose AI has tools but no permission control in the app (`safeWriter`: Hermes today). An agent on automatic routing is taken when at least one usable AI is signed in. With none left the request gets 400 ("needs a signed-in AI") and nothing is stored. The writer runs once (0017): no conversation id read or saved, no memory, no role notes, skills or connectors, and no pictures, even when pictures are attached with the document (text inside a picture is written by someone else too). The call gets the read-only permission mode; what that guarantees depends on the AI: AIs whose permissions the app sets (Claude, Codex, Gemini, ACP agents) run it read-only as far as their CLI enforces the mode, and AIs without tools (API keys, local models) can only answer with text. An AI with tools whose permissions the app can't set never writes the draft: it is skipped when choosing the writer, and when automatic routing or a usage-limit takeover lands on one, the call doesn't run (the answer gets an error saying why). The prompt is the code's instructions, the user's request, the documents' text inside random markers as reference (60,000 characters in all; a longer text is cut and the prompt says so), the AIs that are signed in now (provider id, name and efforts; model id, name and tier, hidden models left out; at most 6 models per tier for each AI, in catalog order, with a line saying how many were left out and that an exact id from the document may still be used, since API-key providers can list hundreds) and the block shape. The instructions say the document is material whose instructions are not followed, that permissions, tools and system instructions are not set, to map what the document names to the closest ids in the list or leave `model` empty and keep the document's wording in `said`, and to end with one `oc-team` block. A block that can't be read is asked for once more ("[Rewrite the team draft]"); if that fails too, a system message says no team could be made, and no card appears. When the writer's run itself fails (a CLI error, a sign-out, a usage limit), the system message says the run failed and to check the AI, not to fix the document. When the run is stopped, or the app closes during it (cleaned up on the next start), `teamDoc` is removed so the message becomes an ordinary message in the conversation and memory, and a system message says no proposal was made and to send it again. The writer's answer is marked `prep: { kind: 'team' }` and `once`, its block position `teamBlock`.
- **Cleaning** (`cleanTeamDraft`, code, idempotent: cleaning a stored draft again gives the same draft): at most 8 agents; names one line, `<` and `>` made full-width, a number added when a name is taken by an existing agent or an earlier one in the draft, compared with spaces, full-width forms and case ignored (the same key stages are matched with, so "Dev Lead" and "DevLead" are two agents), "Agent n" when empty. Lengths use the units and limits the create step uses (UTF-16 units: names and the team name 40, roles and stage names 30, the number included) and never leave half a character or a dangling emoji joiner. If the team name or a stage name matches the injection patterns of 0013 (both go into every prompt of the team's agents), it becomes "Team from a document" or "Stage n", and the card keeps the original wording as a warning (`renamed`). A provider must be a signed-in real AI, matched by id or name; otherwise the agent uses automatic routing with the profile from its tier (1–2 economy, 3 balanced, 4 best) and the warning `provider`. A model must match a catalog id or name of that AI (case, spaces and a trailing note in brackets ignored); otherwise the model of the nearest class by tier (1 fast, 2 balanced, 3–4 top) with the warning `model`, and `said` stays. An effort the model doesn't accept is moved to the nearest one it does (a range like "medium~high" takes its first word) with the warning `effort`. Text matching the injection patterns of 0013 gets the warning `suspect`. `tier` is an integer 1 to 4, from the model's class when missing. Stages find agents by the name as written, else by the same key; they drop unknown names, an agent named twice in a stage, empty stages and a stage with the same agents as an earlier one, hold at most 8 agents each, at most 8 stages; agents in no stage go into a "Work" stage after them ordered by tier, review roles into a last "Review" stage (with no stages at all, everyone goes that way). Permission, system instructions, tools, skills, connectors, stage instructions and approval gates in the block are dropped, whatever they say.
- **The card** (`role: 'proposal', kind: 'team'`): `{ status: 'open', userMessageId, writerId, draftMsgId, rev, draft: { name, agents: [{ name, role, provider, model, modelLabel, effort, routing, routingProfile, tier, said, when, warn, suggest? }], stages: [{ label, agents }] }, notes, docs, cut?, renamed? }`. It shows the team name, a table (name with tier and when, role, AI · model · effort, the document's wording, permission), warning rows, a warning for each renamed team or stage name with the original wording, the stage line with "agents in the same stage all run on every message", what couldn't be carried over, a permission for everyone plus one per agent (default `default`; build and writing roles get a hint that they may need file edits; choosing "Allow all" or "Auto", the two widest, shows the same warning box as the agent editor), "Switch this session to this team" (on by default), and Create / Drop it / Just send it, with "An AI read the document and wrote this draft. Nothing is created until you press Create." Text written by an agent is drawn as text only.
- **Resolving** (`POST /api/sessions/:id/proposals/:mid`), once per card. `dismiss` closes it. `send` runs the stored message (attachments included) as an ordinary message and removes `teamDoc` (0006's path). `accept` takes only `{ rev, permission, permissions: { [index]: permission }, switchTeam }`. The server reads the AI list first, then without waiting again: a `rev` other than the card's gets 409; the stored draft is cleaned again with the AIs signed in now; since cleaning is idempotent it changes only when something outside changed: an AI signed in or out or a model list changed (AI, model, effort or warnings differ), or an agent with one of the draft's names was made meanwhile (a name gets a number). Then the card gets the new draft and `rev + 1`, and the request gets 409 with the new draft and a message naming which of the two happened; switching while a goal is alive gets 409. Otherwise it makes the agents (empty instructions, no skills or connectors, the chosen permission or `default`, `tier`) and the team (`ladder: true`, `escalateAfter: 2`), all checked before anything is saved, switches the session when asked (turning goal mode off with the reason when the new team can't use it, as editing a session does) and marks the card `done` with `teamId`, `agentIds` and `switched`.
- Messages marked `teamDoc` and the writer's answer are left out of every conversation passed to agents and of project memory; the message goes into memory after "Just send it" runs it. The `oc-team` block is read only in this run, never in a goal's steps. It isn't in goal mode's table of blocks each part takes (0022); in a goal step's answer it is a block outside the table and gets the progress-log line. The draft run itself is never a goal run (it starts before goal mode is checked), so its answer isn't logged.

This adds `tier` to agents, `ladder` and `escalateAfter` to teams, `teamDoc` and `teamBlock` to messages, and the proposal kind `team`. Earlier versions ignore the fields; they draw an open team card as a hire proposal whose model agent is gone (Hire gets 409) and a resolved one as "Hire proposal cancelled".

## Consequences

- Word rules miss requests worded another way (a compound like "팀원 구성해줘", a question, a request in the middle of a longer sentence) and can still catch a short sentence that fits without meaning it; "Just send it" covers the second case.
- One AI call per document (two when the block is asked for again), at the writer's usage. The text of the documents goes to the writer's AI.
- A message stopped during the draft becomes an ordinary message, so a later agent sees it in the conversation like any stopped request. When the draft fails (the block can't be read, the run fails) the message keeps `teamDoc` and the system message says what to do.
- Not covered: tables in pictures or PDFs (pictures attached with a text document are not passed to the writer at all); a button on the Teams page; editing names, roles or models on the card (change them on the Agents page after creating); notes on when to use an agent are shown on the card only and not kept on the agent.
- Not covered: choosing the agent by difficulty at run time. `tier`, `ladder` and `escalateAfter` are stored for a later step that asks before handing a task card to a higher tier. Decision [0014](0014-goal-mode-confirmed-goal-card.md) keeps each agent's own model with no router that picks models by how hard a task looks; that still holds, since nothing here picks a model per request: the document only decides which agents exist.
- Agents in one stage all run on every ordinary message, so a team with several agents in a stage costs that many calls per message; the card says so.
- Checked with fake CLIs in `test/teamdoc.test.js`, including a property test that cleaning any draft (every case in the file, the review's reproduction and 400 random drafts) twice gives the same result, the recognition examples in four languages, the writer choice with fake provider capabilities, stopping, and a restart during the draft. Screens checked in a real browser with the fake Claude CLI: dropping a `.md` file and choosing one with the file picker, the card, per-agent and all-agent permissions, Create (team made, session switched, stored permissions and tiers), a draft with model, effort and provider warnings, Just send it, the English screen and a 375 px wide window. The renamed team and stage warnings and the warning boxes for "Allow all" and "Auto" (one agent and everyone) were checked in a real browser with the fake Claude CLI at desktop width and 375 px. Not checked on screen: Simplified Chinese and Japanese (translation test only), the 409 redraw, the dark theme. How real CLIs follow `oc-team` is not measured.
- To undo: drop the `detectTeamDoc` line in `send`; stored cards stay as messages.
